软件开发工具实践实验报告

课程名称： 软件开发工具实践
姓名： 张陈培骥
专业： 软件工程
实验形式： 个人实践与小组协作
实践目标： 完成从桌面开发环境、代码编辑与版本管理，到 Linux 虚拟机、远程管理和 Web 静态站点部署的完整工具链实践。

本次实践以“构建、管理并部署一个可以访问的静态博客”为主线，将 Windows 桌面开发环境、GitHub 代码仓库、VirtualBox 虚拟机、Ubuntu Server、SSH、SCP、rsync 和 Nginx 串联起来。最终成果同时能够在本地 Hexo 服务、GitHub Pages 和虚拟机 Web 服务器中运行。

一、目标场景与总体架构

本次实践构建的目标场景如下：

  1. 在 Windows 主机中安装 Node.js、npm、Git、VS Code 和 Hexo。
  2. 使用 Markdown 编写博客文章，并通过 Git 管理源码。
  3. 在 VirtualBox 中安装 Ubuntu Server，构建 node1 与 node2 两台虚拟机。
  4. 在 Linux 中完成文件操作、软件包安装、账户管理、权限配置和环境变量配置。
  5. 通过 SSH 从 node1 远程管理 node2，使用 SCP 和 rsync 传输文件。
  6. 在 node2（192.168.56.103） 中安装 Nginx，将 Hexo 生成的静态页面部署到服务器。
  7. 将博客同步部署到 GitHub Pages，实现公网访问。

7.2 文件权限管理

Linux 权限分为所有者、所属组和其他用户三组，每组包含读、写、执行权限。

数值权限 750 表示：

  • 所有者：读、写、执行；
  • 所属组：读、执行；
  • 其他用户：无权限。

7.3 最小权限原则

账户权限不应为了操作方便而全部设置为 777。实验中通过 chmod、chown、用户组和 sudo 配置，按实际需要分配权限，可以降低误操作和越权访问风险。

十一、重点配置与问题排查

11.1 Hexo 初始化时无法连接 GitHub

现象： hexo init 克隆模板时出现连接超时。
原因： 当前网络无法稳定访问 GitHub。
处理：

  1. 检查 Git 和网络连接；
  2. 重新运行初始化；
  3. 项目文件已经生成时，进入目录执行 npm install；
  4. 必要时配置可靠的 npm 镜像，但不在公开仓库中保存账号密码或令牌。

11.2 Git 推送后 GitHub 页面未立即更新

GitHub 页面可能存在短暂缓存或构建延迟。应先确认：

随后检查远程仓库分支是否为 main，并刷新 GitHub 页面。

11.3 SCP 提示文件不存在

原因： 本地文件路径、远程目录或当前工作目录写错。
排查：

先确认源文件真实存在，再使用绝对路径或正确的相对路径传输。

11.4 rsync 同步后远程多出旧文件

普通 rsync 不会自动删除目标目录中的旧文件。需要完全镜像时加入 --delete，但执行前必须确认源目录和目标目录，防止误删。

十三、技术展望与升级方案

本次实践使用 Hexo 作为静态站点生成工具。Hexo 配置简单、Markdown 支持完善，适合个人博客，但仍存在进一步升级空间。

13.1 可替代工具

工具 特点 适用方向
Hugo 单文件部署、构建速度快 大型博客和文档站
VitePress 与 Vue 生态结合紧密 技术文档和课程资料
Astro 支持多种前端组件框架 内容网站和现代前端站点
WordPress 后台管理和插件功能丰富 需要动态内容管理的站点

13.2 可行升级路线

  1. 自动化部署： 使用 GitHub Actions，在推送源码后自动安装依赖、生成静态文件并发布。
  2. 容器化环境： 使用 Docker 固化 Node.js、Hexo 和 Nginx 版本，减少不同计算机之间的环境差异。
  3. HTTPS 与域名： 绑定个人域名，使用 Nginx 或 Caddy 配置 HTTPS。
  4. 备份与回滚： 对源码仓库、部署目录和 Nginx 配置进行定期备份。
  5. 安全强化： 禁止 SSH 密码登录，仅保留密钥认证；限制开放端口；避免使用 root 直接远程登录。
  6. 持续监测： 增加访问日志分析、服务状态监控和部署失败通知。

13.3 网络调研方法

技术选型过程中应优先查阅：

  1. 工具的官方文档和发行说明；
  2. GitHub 仓库中的 README、Issues 和 Discussions；
  3. 社区教程与故障排查记录；
  4. 多种工具的构建速度、维护成本和生态对比；
  5. 与自身部署环境相同的实践案例。
