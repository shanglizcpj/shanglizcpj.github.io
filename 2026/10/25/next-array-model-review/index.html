从 next 数组到模型评审

发表于 2026-10-25分类于 学习实践

今天继续学习数据结构，重点追问了 next 数组，也围绕具体元素的取出过程要求更细的解释。研究方面，我把 REGRIND 的问题从“这篇论文讲什么”推进到“能不能作为 baseline”。项目方面，MathorCup 的工作进入复现归档、结果解释和评审修订阶段。

这篇记录把三个层次分开：我提出了哪些问题，工具和团队留下了什么结果，还有哪些判断需要继续验证。

数据结构 先把不明白的地方问具体

今天我直接提出“详细讲解一下 next 数组”。后面的学习中，又追问“没听明白，详细讲解一下”，以及“我如果取出 a14 呢”。这些问题留下了比较真实的学习状态：看到一个答案之后，我仍需要把中间过程展开，换一个具体对象再检查。

对 KMP，复习时需要抓住的是失配后还能利用哪些已经匹配的信息。next 数组的下标含义、起始约定和跳转位置需要放在同一套定义里理解，不能只背一串数值，再与另一种写法混用。这个检查点可以作为后续手算的顺序：先写清约定，再标出已匹配部分，最后解释下一次比较从哪里开始。

今天先记录这些追问，不把看过解释直接写成独立掌握。具体题目的答案和代码是否正确，还需要回到完整题面与自己的推演过程。

论文阅读 从方法介绍转向基线选择

上午我请助手分析了 REGRIND，随后问“可以作为 baseline 吗”。这个项目研究重定向引导的灵巧操作强化学习。当天讨论主要围绕人类示范、动作重定向、参考轨迹和后续策略学习展开。

作为候选基线，需要先确定自己想比较什么：重定向质量、状态误差下的鲁棒性，还是仿真到真实的迁移。助手提出了先复现、再加入单一改动的建议；目前我还没有在这份记录中给出最终研究方向，也没有可写入的复现或真机实验结果。

这一步的收获可以先落在实验设计上：如果以后进行比较，就要对齐任务、示范、观测条件和训练预算，并保留未修改的方法作为对照。论文里的成功率属于作者的实验，不能提前成为我的项目成绩。

MathorCup 把复现和解释分别核对

今天问题一的收尾 PR 已合并，新增内容主要是复现工具、运行归档和差异比对，而非重新修改模型方案。交付报告记载了另一次 Windows、Python 3.12.14 环境下的完整运行：46 项比较对象中，30 项逐字节一致，14 项只有换行差异，另外两项分别涉及 Python 元数据和极小的 PLS 浮点差异。这样的记录比一句“结果一致”更容易核查。报告中的实跑由 Codex 辅助完成，不能省略工具参与，也不能把新日志倒填成旧环境的记录。

问题三的感官画像评审则把工程检查与科学解释分开。我的账号提交了 Codex 辅助的工程批准，评审报告记录 130 项测试通过；随后的补充意见继续讨论风格差异收缩、连续值与等级显示的差别。工程批准仍然保留，但生成样本缺少实测感官标签，相关组间比较不能写成生成预测准确率，也不能证明缺陷安全。

晚间，问题二的解释评审发现了一个具体分类问题：异戊醇与目标分子不同，但其来源注释含有与目标相符的香蕉描述。原稿把分子身份与描述相容性混在一起，将它归入“仅背景重叠”。我的账号据此提交了修改请求。

随后队友修订了解释记录、重建附表并刷新清单，同时保留“描述匹配不能证明独立致味作用”的限制。修订提交的九项 CI 已通过。截至本次记录截止，PR 仍未合并，旧提交上的修改请求也不能自动当成新提交已获批准。

留下可以继续检查的问题

今天比较有价值的进展，是把问题推进到更具体的位置：算法需要解释跳转依据，基线需要说明比较条件，项目评审需要区分数值一致、描述相容与科学结论。AI 可以辅助展开步骤、重建文件和定位差异，最终记录仍要保留实际做过的部分。

待补充的是：哪些数据结构题已经能够独立推演；REGRIND 是否确定进入复现；问题二修订后的复审，以及团队最终采纳和论文整合是否完成。
