从知识库检索到实验报告：把学习过程写清楚

发表于 2026-10-16分类于 学习实践

今天的学习和实践主要围绕三件事展开：继续调试 LabMentor 的知识答惑功能，修改家庭用电曲线异常筛查实验报告，以及借助 Codex 整理生涯发展报告。几项工作都到了需要检查具体内容的阶段：问答要追查检索来源，实验要解释方法和边界，个人经历也要落到自己实际做过的事情上。

  2. 二、实验报告修订：说明参数，也说明方法的边界
  3. 三、Codex 中的生涯报告：用真实经历梳理下一步
  4. 四、今天留下的待确认事项

一、知识库完成本次交付：从补充问答到复测

今天继续处理“知识答惑”三合一知识库。过程中，我补充了资料，也围绕具体问题检查智能体的回答，例如共射放大电路的饱和失真、示波器使用和直流稳压电源操作。

一个典型问题是“共射放大电路出现饱和失真，怎么从波形上判断”。早先的回答存在削波方向错误，后续回答明确了适用条件：对于典型 NPN 共射电路，以集电极对地电压为输出，饱和失真表现为下沿被削平。这里需要同时交代电路类型和观察位置，不能只留下脱离条件的口诀。

补充资料以后，我继续追问如何检测是否通过，并对不同检索方式下的表现进行排查。晚间的讨论集中在 FAQ 与普通文档检索之间的差异：同一个问题，在不同设置下可能得到不同回答，因此需要查看命中的内容，再判断问题出在资料、召回还是后续回答环节。

接近晚上十点时，我选择关闭 FAQ 功能，使用普通 Markdown 文档检索，并选择补充单独的第 34 条问答文档。上传结束后，我继续进行了检测，随后确认运行恢复正常。

晚间补充的测试记录中，共射电路问题给出了测量前提和对应文档来源，示波器波形不稳定与数码管类型判断也列出了问答文档。对于资料未覆盖的仪器参数，回答没有编造数值；面对具体电路故障，回答引导到“诊断教练”；涉及市电与电源短接的提问，则明确了安全边界。这些记录让本次检查覆盖到知识回答、资料不足、功能分工和安全提醒几个方面。

完成这轮检查后，我进一步整理了交付文档需求，包括需要同步回仓库的资料，以及供 Codex 重新扫描仓库、更新工单使用的提示词。今晚已经完成本次交付，这篇博客也随之补上了从资料修订、检索调整到复测交付的完整进展。

这次过程可以留下一个具体的检查顺序：先确认文件内容，再确认检索命中，最后检查回答是否准确、是否对应正确来源。每一层都保留证据，后续修改时才容易比较前后差异。

二、实验报告修订：说明参数，也说明方法的边界

今天还继续修改《家庭用电曲线异常筛查》实验报告。我先让 ChatGPT 汇总修改意见，整理成给 Codex 的完整修改提示词，之后又提交新版报告进行检查，最后继续询问定稿前的修改建议。

这份报告围绕余弦相似度展开：把一天的用电曲线表示为 96 维向量，比较一条平均历史模式和多个相似历史日两种参考方式。当前版本写明了 k=5 的设计理由，同时保留“尚未比较不同 k 值”的范围说明，避免把一次参数选择写成已经验证的最优结果。

报告也将数据划分、核心 NumPy 实现和结果文件对应起来，例如用 metrics.csv 对应指标表，用 validation.json 保存核验记录。这样的组织方式让读者能够沿着方法、程序和结果继续核对。

其中值得单独记录的是余弦相似度的尺度不变性。整条曲线按相同比例放大，方向可以保持不变，所以只比较方向会遗漏纯幅度增长。报告把夜间局部抬升、时间错位和整体放大分别讨论，也区分了受控扰动与真实故障。这里记录的是报告中的方法与结论，完整复现过程和运行证据仍需要在后续整理中对应到具体文件。

三、Codex 中的生涯报告：用真实经历梳理下一步

今天在 Codex 中，我从生涯发展报告的 Markdown 写作脉络开始，补充了课程、项目经历和研究兴趣。

目前我是软件工程专业大二学生，接触过 Python、JavaScript、C 和 C++，其中 C++ 的学习还有困难。回顾过去的 OCR 相关竞赛，我主要承担网页编写和知识库连接工作，遇到过连接与启动问题，需要逐级排查，最后提交了报告，但没有通过初赛。这些经历属于过去的实践，今天做的是重新整理它们。

我也明确了下一阶段想探索深度学习研究，尤其是具身智能。Codex 据此整理了个人报告初稿，并提供 Markdown 和 PDF 版本。研究兴趣仍处于探索阶段，报告中需要继续区分已有工程经历与未来研究计划。

四、今天留下的待确认事项

  • 实验报告中的运行记录、源码和图表是否已经整理为完整的复现材料。
  • 生涯报告中，补充一次具体连接故障的排查过程，让项目经历更加具体。

今天的知识库工作已经完成本次交付。实验报告与生涯报告的补充细节仍保留在上面的清单中，后续再根据实际材料完善。
