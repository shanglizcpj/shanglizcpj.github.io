从 Rust 运行入口到实验与论文交付

发表于 2026-10-31分类于 学习实践

今天继续接触 Rust 基础，从输出语句问到 Cargo，再回到 Rustlings 的运行方式。代码里的一行语句、项目构建工具和终端里的命令，看起来都与“运行”有关，但各自负责的事情不同。今天的笔记先把这些关系整理出来，另一部分工作是把旧实验数据整理成能打印使用的材料，再补记上一份日记没有覆盖到的论文审改与交付检查。

本文按北京时间整理至 10 月 31 日 22:00。论文部分的提交实际发生在 10 月 30 日白天，属于补记，不计作今天新完成的开发。

一 从输出语句问到程序入口

傍晚，我先询问 Rust 中 print 和 println 的区别，后来又确认 fn main 是否就是主函数。这些都是很小的语法点，却决定了怎样读懂一个最简单的程序。

整理笔记时，可以先记下两件事：print! 输出内容时不自动换行，println! 会在末尾加上换行；这里的感叹号表示宏调用。对于常见的 Rust 可执行程序，fn main() 是理解程序入口的起点。输出宏的具体行为可对照 Rust 标准库文档。

今天的记录能确认这些问题已经提出，但还没有我独立编写、运行并比较输出结果的完整反馈。因此先保留概念笔记，不把它写成已经完成一组练习。

二 Cargo 与 Rustlings 的作用要分开

随后，我追问 Cargo 是用来做什么的、当前练习是否需要它，以及 Rustlings 是否必要。把几个名称分开之后，运行过程才比较容易理解。

Cargo 是 Rust 的构建系统和包管理器。对于 Cargo 项目，cargo check 主要检查能否编译而不生成可执行文件，cargo build 构建程序，cargo run 则负责构建并运行。这里整理的是工具各自的用途，不代表这些命令今天都已在我的电脑上成功执行。Rust 官方教程 对这几种操作作了区分。

Rustlings 是练习工具，不能把它与 Rust 语言或 Cargo 混为同一件事。学习语法、让单个程序运行，以及使用练习工具检查答案，可以分别验证。

今天上传的一张编辑器截图中，variables1.rs 旁边显示了 M 修改标记；另一张终端截图显示，执行 rustlings --version 后，PowerShell 返回 CommandNotFoundException。这说明当时终端没有找到这个命令。它不能单独证明 Rust 没装好，也不能确定是安装、路径还是其他环境问题。

对话中已经提出了使用 Cargo 继续运行的思路，但尚未看到后续成功输出。现阶段能记录的是文件存在修改标记、命令调用遇到问题；练习是否通过、工具是否恢复可用，都还需要下一步结果。

三 实验材料要适合实际打印使用

上午，我继续整理此前的电流表校准数据，最初要求生成包含表格和校准曲线的 Word 文档。随后，我把需要的交付物说得更具体：只要能够裁剪下来贴到报告上的表格和曲线，并把数据表的横纵方向互换，整体生成直接打印的 PDF。

这里还有一个实际问题：我反馈前面的文件链接无法使用，要求新链接能够点开下载。因此，内容排好以后，是否能下载、打印并贴进报告，也是这次整理要检查的部分。

下午，我又提出写一段简短的实验心得。这些请求针对已有实验数据和报告呈现，没有新的测量记录。当前没有我确认成功下载或打印的反馈，也不把助手代写的“已经掌握”当成我的学习完成证明。准确度等级等数值需要以原始数据和仪器条件核对，本篇不重复未经本轮复算的结论。

四 补记昨日未收入的论文审改

MathorCup 的新候选提交发生在 10 月 30 日 14:13，随后的第三轮模拟审查报告发生在 15:17。这两份材料没有进入昨日草稿，今天补充记录；此前的正文重写与冻结附录复用过程不再展开。

这一轮先修正了缺失值处理的表达。训练中使用中位数构造模型坐标，与恢复原始记录是两回事；未冻结的非缺陷缺失字段可以产生候选值，但不能称为恢复了实测数据。新稿用具体样本说明：两项非缺陷字段产生候选值，原本缺失的双乙酰仍保留缺失。

表格与摘要也补上了就地说明。表格写清数值处于 log10 尺度、括号中的单位是取对数前的单位，并区分真实样本与生成样本。摘要同时保留完全一致率和一级容差一致率，避免只呈现较宽容口径下的结果。相关审计代码增加了保存值与文稿对应关系的检查；研究源码、原始数据和冻结结果没有因此改变，也没有新增科学实验。

交付检查中还遇到过环境问题。作者报告，首次普通沙箱检查出现三项错误，涉及文档依赖缺失及 MSYS 访问拒绝；保留失败日志、补齐隔离依赖后，在新的干净检出中重跑，32 项命令和 323 项测试通过。这是作者记录的验证过程，本次博客整理没有重跑这些命令。

第三轮 AI 辅助队内模拟审查报告称，前一轮五项 P2 问题已经修复，未发现新的 P1/P2，并报告了数值复算和 36 页文稿检查。它没有复跑作者的全部命令，也没有核验最终匿名 ZIP 或平台提交回执。模拟审查报告与正式批准仍需分开；截至本次核对，两项相关 PR 均未合并、未有正式 Review。

五 留下可以继续核对的结果

这次整理里，Rust 的命令报错和论文交付检查有一个共同点：要先确定自己正在检查哪一步。编辑器显示改过文件，还需要运行结果；测试报告写着通过，也要看它覆盖的是哪个版本和哪份交付物。

后续最值得补入的，是 Rustlings 或 Cargo 的实际运行反馈、variables1 的检查结果，以及电流表表格与曲线是否已成功下载打印。论文部分则继续区分技术检查、正式复评与最终提交，不把它们合成一个完成状态。
