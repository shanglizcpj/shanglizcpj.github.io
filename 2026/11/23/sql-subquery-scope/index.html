同样是求平均分，子查询少一个条件会怎样？

发表于 2026-11-23分类于 学习实践

今天看 SQL 题时，我追问子查询为什么不成立，后来又问有没有别的方法。做这种题，先抄一遍语法容易，难的是看出内层到底在用哪些行。今天这篇笔记另外编一组数据，只比较两个看起来很像、实际回答了不同问题的查询。

一个“平均分”，两种范围

目标是找出高于自己所在小组平均分的记录。下面是为说明概念构造的数据，不是原题截图：

编号小组分数
1A60
2A70
3B80
4B100

A 组平均分 65，B 组平均分 90，全表平均分 77.5。用这几个数，不看 SQL 也能先判断：应该留下 2 号和 4 号。如果写出的查询没有留下 70 分，却留下 80 分，就优先查一查是不是把“同组”算成了“全表”。

把外层的小组带进内层

SELECT r.id, r.team, r.score
FROM results AS r
WHERE r.score > (
    SELECT AVG(x.score)
    FROM results AS x
    WHERE x.team = r.team
)
ORDER BY r.id;

内层的 x 是拿来求平均的记录，外层的 r 是当前要判断的记录。x.team = r.team 把两边连起来：给 2 号算平均时，只看 A 组；给 3 号算时，只看 B 组。内层引用了外层列，所以这是相关子查询。SQLite 官方文档：相关子查询

容易漏的是这条比较条件。删掉它，查询仍然可以执行，但内层变成全表平均 77.5，结果就变成 3 号和 4 号。遇到“结果不成立”，不妨先分清是语句无法运行，还是运行成功却筛错了数据。

换个写法，把平均分先列出来

我也想把“还有什么方法”留在笔记里。这个例子可以先按小组求平均，再把每条记录和本组的平均分连起来：

SELECT r.id, r.team, r.score
FROM results AS r
JOIN (
    SELECT team, AVG(score) AS mean_score
    FROM results
    GROUP BY team
) AS m ON r.team = m.team
WHERE r.score > m.mean_score
ORDER BY r.id;

这组数据用两种正确写法都得到 2 号和 4 号。第一种把“用哪组”写在子查询里，第二种把小组平均分做成一张临时结果，再写匹配条件。哪一种执行得更快，不靠这里的四行数据判断。

下次遇到类似的题，我会先把要求写成一句自然语言：哪条记录，要和哪一批记录算出的什么值比较？ 如果两种写法看起来都对，就挑一条在全表平均和组内平均之间的记录，手算一下它到底该不该留下。
