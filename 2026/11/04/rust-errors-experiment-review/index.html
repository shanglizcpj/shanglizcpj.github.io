从 Rust 错误传播到实验材料核对

发表于 2026-11-04分类于 学习实践

今天的问题从 Rust 中一个表达式会不会修改原值，延伸到函数怎样返回错误。与此同时，我继续调整霍尔实验的打印材料，也提交 SQL 实验报告寻求改进建议。这篇笔记重点记录每一步正在处理的对象，以及哪些结果仍需验证。

本文按北京时间记录至 11 月 4 日 22:00。代码分析与实验材料审阅不等同于本地运行或最终验收。

一 返回新向量和修改原向量

早上我问了 Rust 非引用传值与 Copy 类型能否借用，随后贴出 v.iter().map(|element| element * 2).collect()，追问“这个不是可以进行改变吗”。

在这段函数中，v 是对向量的共享引用；iter() 遍历元素的引用，map 为每个元素计算新值，collect() 把结果收集成新的 Vec<i32> 并返回。这里的数字变大，是新向量中的值发生变化，不表示原向量被原地修改。是否改变原数据，要看访问方式和实际执行的操作，而不能只看表达式里出现了乘法。

这是一段代码阅读笔记；目前没有对应的本地运行输出或练习通过反馈。

二 从 Result 到错误传播

晚上我继续追问 error、match 与 ? 的关系，也贴出了返回 Result<(), ParseIntError> 的 main。Result<T, E> 用 Ok(T) 表示成功、Err(E) 表示错误；match 可以分别处理两个分支。对于返回 Result 的表达式，? 在成功时取出内部值继续执行，出错时提前返回，并在需要且存在相应转换时转换错误类型。Rust 官方教程对这些路径有说明。

随后我贴出 errors5.rs，其中既有字符串解析，也有正数校验，两处都可能返回错误。我问为什么返回类型使用 Box<dyn error::Error>，又追问 impl 的含义。这个类型为不同的、满足相应条件并可转换的错误提供共同的返回形式；Error 本身是描述错误行为的 trait，具体类型的实现仍需满足相应要求，可对照标准库文档。

练习代码仍标有未完成提示，现有记录没有编译和测试结果，因此这里只整理问题与语义，不写成已经通过。

三 霍尔表格与曲线：尺寸和读数都要核对

接着昨天的材料整理，今天我反馈两个 PDF 都无法加载，并进一步明确尺寸：表格宽度与图宽合计为 12 厘米，表格和图的高度保持一致，同时表内保留原始读数和计算结果。

新生成文件的说明写的是每张曲线图外框宽 12 厘米，这与我要求的“表加图总宽”并不完全一致，需要重新测量确认。文件中还标出表三两处涂改读数采用了推定值，须回到原始记录核对。目前没有最终下载、打印或验收确认。

这次调整把问题从“图小一点”变成了可以检查的具体条件：总宽怎样计算、表图如何对齐、原始数据是否保留，以及不清楚的数字如何标明。

四 SQL 报告中的一条审阅意见

今天我上传 SQL 实验报告，请求检查问题和提出改进建议。审阅中有一个具体例子：报告提到 18 条成绩，而对应查询使用聚合函数且没有 GROUP BY。这里需要区分参与计算的输入记录数量，与查询返回的汇总结果行数。

报告本身记载了数据库环境和运行过程，但本次审阅没有重新连接本机执行。关于外键条件、别名范围等内容也只是审阅意见；是否修改报告并重新验证，还没有确认。

五 待补充

今天的共同问题是：变化发生在哪里，结果又能证明什么。Rust 中需要区分新值与原值、成功值与错误；实验材料中需要区分文件生成与尺寸、读数核对；报告中则需要区分数据行数与结果行数。

待补充的是 Rust 练习的实际编译输出、霍尔表三两处原始读数和新版打印尺寸，以及 SQL 报告是否修改并重新执行。本次未取得可证明当天本地 Codex 修改或测试通过的记录，不据此断言当天没有其他操作。
