从关系建模到口述材料的准确表达

发表于 2026-11-05分类于 学习实践

今天，我从数据库题目中的几条连线，问到了访谈文字的来源，再到 Rust 表达式和神经网络参数。问题看起来分散，却都需要先说明一个对象代表什么，再判断它与其他对象的关系。

本文按北京时间记录至 11 月 5 日 22:00。以下记录已经提出的问题、可读材料和概念分析；尚未验证的练习结果与文稿内容单独保留。

一 注册分店与购买分店，不能只看连线

早上的数据库题目围绕一家便利连锁店展开：职工只能在一家分店工作，会员只能在一家分店注册，但注册之后可以在所有分店购买商品。题目要求画出 E-R 图，转换为关系模式，再讨论 BCNF。

我先要求使用长方形、菱形和椭圆表示实体、联系和属性，随后追问：“分店和购买为什么要连？”又指出题目中没有“类别编号”这一说法，并要求根据自己上传的手绘图转换关系模型。

这里最关键的区别，是会员的注册地点与某次购买的发生地点。会员编号可以用于确定注册分店，却不能仅凭会员编号确定每次购物所在的分店。若要记录交易发生在哪里，购买联系中的分店信息就有自己的含义。用一个“分店”字段同时代替两种含义，会把业务规则混在一起。

接着，我问了主码和外码能否重合、什么是超码，以及“分店到会员再到购买没有传递吗”。主码负责唯一标识本关系中的记录，外码负责引用其他关系，两种作用可以落在同一属性上；但组成购买记录的候选码，还需要考虑同一会员重复购买同一商品的情况。

判断 BCNF 也要落实到函数依赖：在某个关系模式中，每一条非平凡函数依赖的决定因素都必须是超码。E-R 图上能沿线走到另一个实体，并不直接证明存在传递函数依赖。具体怎样分解，仍须先列清字段含义、候选码和业务约束。

这次讨论已经推进到这些具体问题，但没有足够依据把生成的关系图视为最终正确答案，也没有数据库建表与约束测试记录。

二 访谈整理：修订信息，也保留材料性质

午后，我请求把一份教师访谈录音整理成普通 Word 文稿。生成稿之后，我又明确要求修正到校年份，并反馈文件无法下载。现有修订文稿可以读到相应修改，整理说明也注明它是方便阅读的问答稿，删减了口头停顿和重复表达，并非逐字稿。

这里有两件事情需要分别确认：文字是否准确，以及文件能否真正下载和使用。修订文件已经出现，后续下载成功与否仍没有确认；本次记录也没有逐句核听原始音频，所以不把整理后的句子直接作为已经核准的受访者原话。

另一份材料是校史剧《选择》结束后的公开发言。我在请求转录时明确写了“标明不是专访”，之后又询问它能否体现“国家大事，千万尽力”的杭电精神。

现有 Word 稿的标题和材料说明均标为公开发言、非专访，并保留了多处“待核”与大致时间。有些涉及同音词、姓名或数字，正式引用前仍应回到录音核对。公开活动发言与针对课程开展的访谈，来源和采集方式不同，应在报告中分别说明。

今天推进的是素材整理与使用方式的讨论。课程报告是否完成、哪些片段最终采用，以及引用与公开传播的具体范围，都还没有确定。这里也不转载尚未核准的发言内容。

三 Rust：最后一个表达式为何没有分号

昨天记录了错误传播，今天我继续问到 panic! 与 Result，晚间则把问题落到 trait 和一个具体方法上：

pub trait Licensed {
    fn licensing_info(&self) -> String {
        String::from("Some information")
    }
}

我的问题是：“函数内不需要分号吗？”

这段 trait 为 licensing_info 提供了默认实现。方法要求返回 String，末尾的 String::from(...) 是尾表达式，它的值就是方法的返回值。如果在这一行末尾加上分号，又不另外返回字符串，函数体的结果会成为 ()，与声明的返回类型不符。

因此，分号需要结合语句与表达式的位置理解，不能统一按“每行结尾都加”处理。这是对贴出的代码所做的语义分析，尚没有对应的编译输出或练习通过记录。

四 神经网络：从输出概率问到参数更新

晚间的另一组问题从前馈网络课件开始。我依次问到 batch size、二分类输出、十分类概率、one-hot、正则项和损失函数，最后追问“调 w 和 b 是什么算法”“梯度的反方向是什么意思”以及反向传播。

这些概念可以沿计算过程整理：

  • 网络先根据权重和偏置计算输出。二分类中常用 sigmoid；互斥的多分类问题中常用 softmax 将多个分数归一化。
  • one-hot 描述真实类别，损失函数比较预测与标签。对单个 one-hot 标签样本，交叉熵可写为真实类别预测概率的负对数。
  • 反向传播利用链式法则计算损失对参数的梯度；梯度下降等优化方法再依据梯度更新权重和偏置。
  • 负梯度是当前位置的局部下降方向，步长仍然重要，不能据此保证每一步都降低损失或找到全局最优解。
  • 正则项加入额外约束或惩罚，帮助控制模型复杂度。训练损失下降，还要结合验证数据判断泛化表现。

现有材料是课件与概念追问，没有训练代码、损失曲线或模型评估结果，因此这里只整理计算环节，不记录为已经训练成功。

五 待补充的验证

这一天的学习记录，可以分别落到几个可检查的问题上：数据库字段是否保留了正确的业务含义，口述材料是否保留了真实来源，Rust 表达式是否满足返回类型，网络训练中又是哪一步负责计算梯度、哪一步负责更新参数。

接下来可补充的是购买关系的完整候选码与函数依赖、文稿下载和拟引用片段的核听结果，以及 Rust 编译或神经网络计算练习的实际输出。当天可读取的任务记录能确认部分文稿产物存在，但本次未取得足以证明新增代码修改、数据库重跑或测试通过的完整操作证据；这不代表当天没有其他本地操作。
