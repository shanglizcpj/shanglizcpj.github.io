远程开机没成功之后：把设置、测试与结论分开

发表于 2026-11-14分类于 学习实践

本文记录截至当日 22:00（北京时间）的情况，后续进展见之后的日志。

今天尝试配置笔记本的远程开机功能，最后留下的结果不是“成功”，而是一个需要继续拆分的问题：我在 BIOS 中找到了相关设置，但完全关机后，使用手机 5G 或其他网络测试，仍然无法远程开机。

这篇记录按截图和实际反馈整理过程，再补记昨晚关于 Token 用量的一个问题。两件事有个共同点：界面上看见了一个状态或数字，还需要确认它究竟能证明什么。

一、先对照实际 BIOS，而不是照搬教程界面

下午，我把远程开机教程和自己电脑的 BIOS 照片放到对话中，询问应该怎样操作。电脑是华硕 FX608JMR，实际界面与教程里的示例并不完全相同。

照片记录了从简易模式到高级模式，再进入网络堆栈设置的过程。其中能直接确认的内容是：

  • 高级页面中的 ErP 显示为关闭。照片没有展示它原先的状态，因此这里不把它写成当天新完成的一次修改。
  • “网络堆栈”页面先显示关闭，后续照片显示开启。
  • 后一张照片同时显示 IPv4 PXE 支持开启、IPv6 PXE 支持关闭。

我还专门纠正了一处识图判断：“我默认 ipv4 是开启的。”这不是我又完成了一个新配置，而是对原有状态的澄清。

整理时核对的华硕笔记本 WOL 官方说明确实包含进入 Network Stack Configuration、启用 Network Stack 的步骤，同时还要求检查 Windows 快速启动和有线网卡的唤醒权限。因此，“网络堆栈已经开启”可以作为一个配置检查点，但不能替代整条唤醒链路的验证。

截图也没有记录保存退出后的配置复查。能看见设置值，不等于已经验证设置持久生效，更不等于远程开机成功。

二、把“无法开机”补充成明确的测试条件

15:46，我反馈“无法完成远程开机”。随后进一步说明：

完全关机后无法远程开机。测试使用的是手机 5G 或其他网络。

这条补充比单独一句“失败了”更有用，因为这里同时涉及两个变量：电脑处于什么电源状态，唤醒请求又是从什么网络发出的。

电源状态不能只看“屏幕黑了”

华硕的官方说明提醒，部分机型不支持从关机状态唤醒。这意味着不能仅凭 BIOS 菜单存在，就认定这台电脑一定支持关机唤醒；也不能凭一次失败就认定它完全不支持 WOL。

还有一个容易忽略的区别：Windows 的快速启动关机与完整关机并非同一种底层状态，外观上却可能相同。微软文档也区分了睡眠、休眠、快速启动和 S5 软关机，具体唤醒能力还受固件与硬件影响。Microsoft：System power states

因此，我当时说的“完全关机”应先保留为测试时的描述，不能在没有进一步检查的情况下直接改写成“已确认处于 S5”。

异网测试还多了一段传递路径

手机使用 5G 或其他网络，与在电脑所在局域网内发起测试，不是同一组条件。华硕的路由器文档展示了一种由路由器向局域网内电脑发送唤醒包的方式，但这不代表我的网络已经具备相同能力。华硕路由器 WOL 说明

结合现有记录，只能提出一个待验证的方向：除了电脑端配置，还需要检查唤醒请求怎样到达电脑所在网络。当前没有数据包到达证据，也没有局域网对照结果，所以暂时不能断言问题就在 5G、路由器或者某个 BIOS 开关上。

三、下一步要补的是对照结果

下面是根据这次记录整理出的后续验证顺序，不是已经执行完的实验：

  1. 先核对实际支持的电源状态、Windows 网卡唤醒设置及配置是否保存，不继续盲目切换 BIOS 选项。
  2. 保持电脑的供电和连接条件一致，先在同一局域网内测试设备支持的睡眠或休眠唤醒。
  3. 再单独测试关机后的唤醒，记下实际关机方式。
  4. 如果局域网测试成功，再比较手机 5G 或其他网络下的结果，检查跨网络传递路径。

目前能填写的记录很少：

条件当前证据
同一局域网，睡眠或休眠尚无测试结果
同一局域网，关机尚无测试结果
手机 5G 或其他网络，用户描述为完全关机我反馈无法远程开机

这张表没有把问题解决，却把“还不知道什么”留了下来。后面无论成功还是失败，都能与今天的条件比较，而不是重新从一句“远程开机不行”开始。

四、前日晚间补记：Token 总量不等于生成量

11 月 13 日 22 点之后，我还问了 DSH 桌面端显示的 Token 数量是不是两千万，并补充自己使用的是本地部署模型。这部分晚于上一篇的截止时间，所以放在今天补记，不算作今天新做的测试。

当时一张简略截图显示约 22.9M tok；稍后的明细截图显示：

界面字段显示值
Token 用量23,239,299
未缓存输入235,040
缓存读取22,880,348
输出123,911

后三项相加恰好等于总量。至少就这张截图的口径来说，不能把两千多万的“总量”直接写成电脑新生成了两千多万 Token；界面另有一个明显更小的“输出”字段。

这张截图也没有提供统计时段、实际请求链路或生成耗时。它能帮助辨认字段，却不能单独证明本地推理速度、某个模型已经接入成功，或者具体如何计费。之前留下的模型测速问题，也不能用这个累计数字代替答案。

今天留下的结论

这次记录里，配置状态、实际结果和统计口径需要分开写：网络堆栈页面显示开启，是截图事实；异网关机唤醒失败，是我的测试反馈；失败原因仍是待验证的问题。Token 明细也是如此，先看字段，再决定能够得出什么结论。

远程开机还没有跑通，现阶段最值得补上的，是同一局域网内的对照测试，而不是提前给某一个设置或网络环节定责。
