Rust 与 SQL 学习笔记：共享了什么，保留了什么

发表于 2026-11-09分类于 学习实践

今天上午，我围绕 Rust 的智能指针连续问了几个问题：Arc 是什么，clone 做了什么，Cow 的 Owned 和 Borrowed 又有什么区别。下午看 SQL 连接时，我继续追问：“几行怎么判断，由外码决定吗？”

这篇笔记把两组问题放在一起整理。读代码或查询语句时，先说清楚操作的对象，再判断它改变了什么，引用计数和结果行数就有了具体的依据。

一、Rc 的引用计数，数的是同一份数据的所有者

我贴出的 rc1.rs 用太阳和行星表示共享所有权。开头创建一个太阳，后面的行星通过 Rc::clone(&sun) 持有它。

这里要区分两个操作：

Rc::new(Sun {})   // 创建新的 Sun，由一个新的 Rc 管理
Rc::clone(&sun)   // 新增一个指向原有 Sun 的 Rc

第二种写法增加的是同一份数据的强引用计数，不会再创建一个太阳。sun 本身加上八个行星各自持有的 Rc，才对应强引用计数为 9 的情况。这与 Rust 标准库对 Rc 的说明一致。

当天贴出的代码里，前五个行星使用了 Rc::clone，但土星、天王星和海王星分别使用了 Rc::new(Sun {})。它们因此没有加入原先那个太阳的引用计数。代码还在中途销毁了地球、金星和水星，结尾却再次对这三个变量调用 drop，存在重复使用已移动值的问题。

因此，不能沿着代码旁边的“7 references”“8 references”“9 references”注释直接往下数。需要先检查每个行星究竟指向哪一个 Sun，以及它是否已经被销毁。

这道练习要求八个行星共同持有同一个太阳，对应的修改思路是：创建行星时统一克隆已有的 Rc，并保证每个行星只销毁一次。后续我已经完成了 rc1.rs 的修复，这里保留最初代码中的问题和对应的修改依据。

Arc 可以放在旁边比较：它使用原子引用计数支持跨线程共享所有权，但内部数据仍须满足相应的线程安全条件。需要共同修改数据时，还要考虑同步方式，不能仅凭外面包了一层 Arc 就认为任何访问都安全。参见 Arc 的线程安全说明。

二、Cow 是否克隆，要看原来的状态和实际调用

cow1.rs 中的 abs_all 遍历整数，只在遇到负数时调用 to_mut()，再把它改成正数。

根据当天贴出的代码，四组测试可以整理成下面的状态变化：

初始输入是否进入修改分支返回时的状态
借用切片 [-1, 0, 1]是Owned
借用切片 [0, 1, 2]否Borrowed
拥有 Vec，内容为 [0, 1, 2]否Owned
拥有 Vec，内容为 [-1, 0, 1]是Owned

这张表里，最容易混淆的是第三行：没有修改，结果仍然可以是 Owned，因为传入时就已经拥有数据。

更准确的判断方法是看 to_mut()：它在当前为借用状态时克隆数据并取得所有权，已经拥有数据时则返回对现有数据的可变引用。在这道题里，调用恰好放在负数分支中；若在别的程序里直接对借用状态调用 to_mut()，即便随后没有真正改动元素，也会发生转换。参见 Cow::to_mut 文档。

所以，判断 Cow 的状态，需要同时看输入的来源和执行过的操作。当天代码里的四个匹配分支可以据此解释，后续我也已完成 cow1.rs 练习。

三、SQL 连接，先数匹配组合，再看保留规则

下午的 SQL 提问从笛卡尔积、内连接延伸到左连接、自连接和交叉连接。其中一个具体疑问是：“那为什么不是五行三列？”

对于没有分组、去重等额外处理的简单连接查询，可以把行数和列数分开看：

  • 结果行数取决于数据之间满足连接条件的组合，以及连接类型对未匹配行的处理。
  • 输出列由 SELECT 列表决定。只选择两列，并不意味着结果只能有两行。
  • 外键约束会影响允许存在的数据关系，但仅知道“这里有外键”，仍不足以直接算出结果行数。

下面用一组简化数据说明，它不是当天原题的数据。假设学生表中有甲、乙、丙三人，选课表有三条记录：甲选了 2 号和 5 号课程，乙选了 2 号课程，丙没有选课。

按学生编号连接时：

  • INNER JOIN 得到 3 行。甲对应两条选课记录，因此出现两行；乙出现一行。
  • 学生表放左侧的 LEFT JOIN 得到 4 行。除了上面三行，还保留丙，右侧选课字段用 NULL 补齐。
  • 两张表直接做 CROSS JOIN 得到 3 × 3 = 9 行，每名学生与每条选课记录组合。

“保留所有学生”也不代表每名学生一定只出现一行。左连接保留的是左表记录的参与资格，一个学生若有多条匹配记录，仍会产生多行。

我还问了：“自连接和内连接有区别吗？”这两个名称描述的角度不同。自连接说明同一张表以不同别名参与连接；内连接说明只保留满足条件的组合。因此，一条查询可以同时是自连接和内连接。

例如，在上面的简化选课表中，要找同时选修 2 号和 5 号课程的学生，可以把同一张表分别看作“2 号课程记录”和“5 号课程记录”，再按学生编号匹配。这个例子中符合条件的只有甲。

四、这篇记录的范围

今天这些问题整理下来，可以留下两套检查顺序：

  1. 看智能指针时，先确认共享或拥有的是哪份数据，再沿着创建、克隆、修改和销毁操作判断状态。
  2. 看 SQL 连接时，先确认每行能够匹配哪些记录，再判断未匹配行是否保留，最后看输出哪些列。
